# Data shapes — Cookbook / Pantry

Source of truth for normalized data contracts shared between the extraction
layer (`server/extract/`) and the backend (`server/`). Backend-agent reads
this file to build DB schema, route handlers, and API responses. Do not
deviate from field names — frontend-agent and backend-agent depend on them.

---

## 1. Draft recipe (extraction layer output)

The object returned by `extractFromUrl` and `extractFromFile` in
`server/extract/index.js`. It is **not persisted**; the route handler sends
it to the client as-is, and the client POSTs back a (possibly edited) copy
when the user clicks "Save to library".

```json
{
  "title":       "Cacio e Pepe",
  "description": "A silky, peppery Roman pasta with just three ingredients.",
  "minutes":     25,
  "servings":    2,
  "cuisine":     "Italian",
  "category":    "Dinner",
  "protein":     [],
  "carb":        ["Pasta"],
  "ingredients": [
    { "name": "spaghetti",          "qty": "8 oz" },
    { "name": "pecorino romano",    "qty": "2 oz" },
    { "name": "black pepper",       "qty": "1 tsp" }
  ],
  "steps": [
    "Bring a large pot of salted water to a boil and cook spaghetti until al dente.",
    "Toast coarsely ground black pepper in a dry skillet over medium heat for 1 minute.",
    "Reserve 1 cup of pasta water, drain, and add spaghetti to the skillet.",
    "Off heat, add cheese and a splash of pasta water, tossing vigorously until creamy."
  ],
  "stepTimes":       [12.0, 34.5, 78.0, 95.2],
  "image":           "data:image/jpeg;base64,... or null",
  "imageCandidates": ["data:image/jpeg;base64,...", "data:image/jpeg;base64,..."],
  "videoToken":      "uuid string or null",
  "filters":         ["Quick", "Vegetarian"]
}
```

Field rules:
- `minutes` and `servings` are **integers** (not strings, not null). Default to `0` when unknown.
- `ingredients[].qty` is a **display string** in imperial units ("2 cups", "1 tbsp", "8 oz", "350°F", or `""` when unknown). Never a parsed number.
- `ingredients[].name` is a plain string. Order is preserved.
- `steps` are ordered imperative sentences; step numbers are positional (1-based display).
- `protein` / `carb` — arrays of the dish's main protein(s)/carb(s) (usually one each); `[]` if the dish has none. Short canonical words (see `server/extract/gemini.js` prompt rule 6).
- `stepTimes` — number array (seconds), **positionally parallel to `steps`** (same length, padded with `0`). Comes from the SAME single Gemini call as the rest of the recipe (the model's `steps` response items are `{ "text", "t" }` objects; `t` becomes `stepTimes[i]`, `text` becomes `steps[i]`). Clamped to `[0, video duration]` via ffprobe when duration is known. `0` means "not visible in the video," not necessarily "the start."
- `image` / `imageCandidates` — cover-photo picker fields; see the extraction-module doc below. Transient, ffmpeg-only (no AI call).
- `videoToken` — references a copy of the downloaded/uploaded video stashed at `server/media/drafts/<videoToken>.mp4`, or `null` if the stash failed (extraction still succeeds regardless — this never blocks a save). Send back as `video_token` on `POST /api/recipes` to claim it; unclaimed drafts are swept after 24h.
- `filters` — subset of the user's current filter labels (from `GET /api/filters`) that the model judged applicable. Folded into the same single Gemini call, not a second request.
- `title`, `description`, `cuisine`, `category` default to `""` when unknown — never `null`.
- The draft carries **no** `id`, `rating`, `favorite`, `source_url`, `source_caption`, `tags`, `created_at`, or `updated_at` — those are absent or added at persist time by the backend/client.

## 2. Persisted recipe (DB + API response)

Stored in the `recipes` SQLite table. JSON columns (`ingredients`, `steps`,
`tags`) are serialized with `JSON.stringify` / parsed with `JSON.parse` by
the backend. All measurements are **imperial** — no metric values are stored.

| Field            | JS type              | SQLite column type | Notes |
|------------------|----------------------|--------------------|-------|
| `id`             | `string` (UUID v4)   | `TEXT PRIMARY KEY` | Generated by backend on creation. |
| `title`          | `string`             | `TEXT NOT NULL`    | Required. |
| `description`    | `string`             | `TEXT`             | One-sentence blurb; empty string default. |
| `cuisine`        | `string`             | `TEXT`             | Free text; e.g. "Italian". |
| `category`       | `string`             | `TEXT`             | Free text; chip-mapped values: "Dinner", "Breakfast", "Dessert". |
| `minutes`        | `integer`            | `INTEGER`          | Total cook time in minutes. |
| `servings`       | `integer`            | `INTEGER`          | Number of servings. |
| `rating`         | `number \| null`     | `REAL`             | e.g. `4.8`; `null` renders as "New" in the UI. |
| `favorite`       | `boolean`            | `INTEGER` (0/1)    | Default `false` / `0`. |
| `image`          | `string \| null`     | `TEXT`             | URL or data string; `null` → UI shows placeholder gradient. |
| `tags`           | `string[]`           | `TEXT` (JSON)      | e.g. `["Vegetarian"]`. "Vegetarian" chip matches tag case-insensitively. Default `[]`. |
| `ingredients`    | `{name,qty}[]`       | `TEXT` (JSON)      | See ingredient shape below. Order preserved. |
| `steps`          | `string[]`           | `TEXT` (JSON)      | Ordered step text. |
| `step_times`     | `number[]`           | `TEXT` (JSON)      | Seconds, positionally parallel to `steps`. May be `[]` or shorter than `steps`. Drives Cook Mode's video seek. |
| `source_url`     | `string \| null`     | `TEXT`             | IG/TikTok link when imported via Path B; `null` otherwise. |
| `source_caption` | `string \| null`     | `TEXT`             | Raw caption fetched by yt-dlp; `null` otherwise. |
| `video_file`     | `string \| null`     | `TEXT`             | Bare filename in `server/media/` (e.g. `<id>.mp4`), NOT a path; `null` if no video. **Internal only — never returned by the API.** The API exposes a derived `has_video: boolean` instead (see `GET /api/recipes/:id/video`). |
| `created_at`     | `string` (ISO 8601)  | `TEXT NOT NULL`    | Set once at creation; never updated. |
| `updated_at`     | `string` (ISO 8601)  | `TEXT NOT NULL`    | Updated on every PUT. |

### Ingredient item shape (used in both draft and persisted recipe)

```json
{ "name": "all-purpose flour", "qty": "1 cup" }
```

- Both fields are strings.
- `qty` is an imperial display string or `""`.
- Items with empty `name` are stripped before persisting.

### JSON column encoding

The backend stores JSON columns as UTF-8 text:

```js
// Write:
JSON.stringify(ingredients)   // '[{"name":"flour","qty":"1 cup"}]'
// Read:
JSON.parse(row.ingredients)   // [{ name: 'flour', qty: '1 cup' }]
```

Default on missing / malformed: parse failures fall back to `[]` for arrays.

## 3. Meal-plan entry

Stored in a `meal_plan` join table. A day can hold multiple recipes; a
recipe can appear on multiple days.

| Field       | JS type             | SQLite column type | Notes |
|-------------|---------------------|--------------------|-------|
| `id`        | `string` (UUID v4)  | `TEXT PRIMARY KEY` | |
| `day`       | `string` (ISO date) | `TEXT NOT NULL`    | `YYYY-MM-DD` format. Survives week rollover. |
| `recipe_id` | `string` (UUID v4)  | `TEXT NOT NULL`    | FK → `recipes.id`. Use `ON DELETE CASCADE`. |
| `position`  | `integer`           | `INTEGER`          | Optional ordering within a day; default `0`. |

`GET /api/meal-plan` returns assignments for the current week (Mon–Sun),
hydrated with minimal recipe fields: `{ id, title, image, minutes, cuisine }`.

## 4. Shopping-list item

Stored in a `shopping_list` table.

| Field      | JS type             | SQLite column type | Notes |
|------------|---------------------|--------------------|-------|
| `id`       | `string` (UUID v4)  | `TEXT PRIMARY KEY` | |
| `name`     | `string`            | `TEXT NOT NULL`    | |
| `qty`      | `string`            | `TEXT`             | Display string; `""` for manually typed items without a unit. |
| `checked`  | `boolean`           | `INTEGER` (0/1)    | Default `false` / `0`. |
| `position` | `integer`           | `INTEGER`          | Optional ordering; default `0`. |

"Add to list" from a recipe de-dupes by `name` (case-insensitive) against
existing items. Manual adds allow duplicates.

## 5. Gemini return JSON contract

The model is instructed to return **only** this JSON shape. The extraction
layer strips code fences, retries once on parse failure, and coerces/defaults
all fields before returning to the caller.

```json
{
  "title":       "string",
  "description": "string — one enticing sentence",
  "minutes":     0,
  "servings":    0,
  "cuisine":     "string",
  "category":    "string",
  "ingredients": [{ "name": "string", "qty": "string (imperial)" }],
  "steps":       ["string"]
}
```

Constraints enforced by the prompt (see `server/extract/gemini.js`):
- Return ONLY valid JSON — no markdown fences, no prose.
- All measurements converted to imperial (weights oz/lb, volumes cups/tbsp/tsp/fl oz, temps °F, lengths inches).
- Dry goods given in grams → prefer volume (cups/tbsp) using standard culinary equivalents.
- Liquids given in ml → convert directly (240 ml = 1 cup, 15 ml = 1 tbsp, 5 ml = 1 tsp).
- Do not invent ingredients; unknown → omit or use `""`.
- Target 5–9 ingredients and 4–7 concise imperative steps.
- `minutes` and `servings` are integers; default `0` if unknown.

## 6. Extraction module interface

### `server/extract/index.js`

```js
// Path B: an Instagram or TikTok link.
export async function extractFromUrl(url: string): Promise<DraftRecipe>

// Path A: an uploaded video file already on disk.
// The caller owns the file's lifecycle (e.g. multer temp file).
export async function extractFromFile(filePath: string, mimeType: string): Promise<DraftRecipe>

// Re-exported for route handlers to switch on err.code:
export { ExtractError, CODES } from './errors.js'
```

Both functions return a `DraftRecipe` (see §1) on success, or throw an
`ExtractError` on failure.

### Error codes (`err.code`)

| Code              | When thrown |
|-------------------|-------------|
| `UNSUPPORTED_URL` | URL is not Instagram or TikTok. |
| `FETCH_FAILED`    | yt-dlp non-zero exit, missing yt-dlp binary, Gemini upload failed, video too large, file I/O error. |
| `NO_RECIPE`       | Gemini returned a valid JSON object with no ingredients and no steps (non-cooking video). |
| `PARSE_FAILED`    | Could not parse Gemini response as JSON after one retry. |
| `TIMEOUT`         | yt-dlp or Gemini request exceeded the time limit. |
| `CONFIG`          | `GEMINI_API_KEY` not set, or `@google/generative-ai` not installed. |

`err.userMessage` is always a safe, friendly string suitable for the UI error banner.

## 7. Required environment variables

These live in `server/.env` (gitignored). Backend-agent should add them to
`server/.env.example`.

| Variable         | Required | Description |
|------------------|----------|-------------|
| `GEMINI_API_KEY` | Yes      | Google AI Studio API key. Free tier. Obtain at https://aistudio.google.com/apikey |
| `GEMINI_MODEL`   | No       | Gemini model ID. Defaults to `gemini-2.0-flash`. |
| `YTDLP_COOKIES`  | No       | Absolute path to a Netscape-format cookies file for yt-dlp. Required for private/age-gated Instagram Reels; TikTok usually works without. |
| `GEMINI_TIMEOUT_MS` | No    | Request timeout in milliseconds for Gemini calls. Defaults to `120000` (2 minutes). |

## 8. Required npm dependency

`@google/generative-ai` must be added to `server/package.json` dependencies.
Backend-agent should run `npm install @google/generative-ai` in `server/`.

Tested against SDK v0.21+. The extraction layer imports both the main
`@google/generative-ai` package and (as a fallback) `@google/generative-ai/server`

## 9. Polling cadence and fallback behavior

Extraction is **on-demand only** — triggered by an explicit user action (paste
link or upload file). There is no background polling.

| Concern | Behavior |
|---------|----------|
| yt-dlp timeout | 3-minute hard kill (`SIGKILL`). Throws `TIMEOUT`. |
| Gemini upload + generation timeout | Configurable via `GEMINI_TIMEOUT_MS`; default 2 minutes. Throws `TIMEOUT`. |
| Gemini file processing poll | Polls every 3 seconds until `ACTIVE` or `FAILED`, bounded by `GEMINI_TIMEOUT_MS`. |
| JSON parse failure | Strips fences, falls back to `{…}` slice, then retries the model once with a JSON-only prompt. On second failure throws `PARSE_FAILED`. |
| yt-dlp missing / bad exit | Throws `FETCH_FAILED` immediately; no retry (user should upload the file instead). |
| IG cookies expired | Treated as `FETCH_FAILED`; `err.userMessage` tells the user to upload the file instead. |
| Temp file cleanup | The `cleanup()` callback from `downloadVideo` is always called in a `finally` block, even when Gemini fails. |
| Empty result | If parsed object has no ingredients AND no steps, throws `NO_RECIPE` rather than returning an empty draft. |

## 10. External-account and credential steps (user must do these)

1. **Google AI Studio API key** — visit https://aistudio.google.com/apikey, sign in with a Google account, create a free API key, and paste it as `GEMINI_API_KEY` in `server/.env`.
2. **yt-dlp binary** — install yt-dlp on the server machine. On macOS: `brew install yt-dlp`. On Linux: `pip install yt-dlp` or download the binary from https://github.com/yt-dlp/yt-dlp/releases. The binary must be on `PATH`.
3. **Instagram cookies (optional)** — if Instagram Reels require authentication, export a Netscape-format cookies file from a browser session (e.g. using the "Get cookies.txt LOCALLY" extension) and set `YTDLP_COOKIES=/absolute/path/to/cookies.txt` in `server/.env`.
